# Команда субагентов «Делим»

Четыре специализированных субагента + главный агент-оркестратор. Почему четыре: у проекта
один внешний шов — интерфейс ядра (ADR 0003), поэтому ядро — один агент (делить его —
пересылка интерфейсов), а оболочка естественно распадается на стейт и UI; приёмка вынесена
за скобки, чтобы вердикт выносил не тот, кто писал код.

Живые определения агентов: `.zcode/agents/` (algo-core, app-state, ui-craft, qa-acceptance) —
подхватятся сессией, открытой в корне проекта. Их системные промпты — первоисточник;
этот документ — чартер: матрица, контракт между агентами и процесс.

## Сводная матрица

| Субагент | Зона ответственности (scope) | Инструменты | Главные артефакты |
|---|---|---|---|
| **algo-core** | Ядро: схема (zod), балансы, сведение (жадный + bitset ≤ 12), кодек (кортежи + lz-string), калькулятор-парсер. Только `src/core/` | Read/Write/Edit/Bash (vitest) | Чистые TS-функции без Vue + три слоя тестов (краевые, property, exhaustive n≤6) |
| **app-state** | Стейт-слой: композабл useTrip, localStorage-адаптер с дебаунсом, useHashRoute, режим зрителя, архив. Только `src/app/state/` | Read/Write/Edit/Bash | Мутации + автосейв + роутинг; производные значения поверх ядра |
| **ui-craft** | Экраны, формы, SVG-граф, текстовая квитанция, стили. Только `src/app/ui/` + стили | Read/Write/Edit/Bash | Мобильный интерфейс с Vue-анимациями; ноль бизнес-логики в компонентах |
| **qa-acceptance** | Дымовые тесты экранов (Vitest) и приёмочные прогоны по user stories | Read/Write/Edit/Bash | Репорты багов и отчёты прогонов; ничего не чинит |
| Оркестратор (главный агент) | Фронт тикетов, назначение, ревью ADR-комплаенса, стабильность интерфейса ядра, GUI-прогоны (браузерная автоматизация) | все | Распределение, слияние, вердикты |

## Контракт между агентами

Единственная точка пересылки — интерфейс ядра из пяти операций (схема, балансы, сведение,
кодек, калькулятор) и два композабла оболочки (useTrip, useHashRoute). Его меняет только
оркестратор: algo-core, которому понадобилось расширить интерфейс, останавливается и
докладывает — у двух других агентов контракт лопнет.

```
ui-craft ──→ useTrip / useHashRoute (app-state) ──→ 5 операций ядра (algo-core)
qa-acceptance ──→ прогоняет только то, что видит пользователь
```

## Что взято из исходной конфигурации заказчика и что подогнано под ADR

Взято как есть: 4 агента + оркестратор; изоляция математики от фреймворка; правило
«integer, Σ балансов = 0»; компактная сериализация кортежами перед lz-string с тестом
roundtrip; property-тесты на рандомных чеках; два флагманских сценария приёмки
(мультивалютная поездка на 4 человек; ссылка → чистый контекст → восстановление один в один).

Подогнано под принятые решения:

| Было в конфигурации | Стало | Основание |
|---|---|---|
| IndexedDB, история поездок | localStorage, одна активная поездка + архив глубины 1 | ADR 0008, 0002 |
| Стор в src/store (подразумевает Pinia) | Композаблы без Pinia | ADR 0009 |
| Кодек в зоне storage-агента | Кодек в ядре (algo-core), storage только потребляет | ADR 0003: один шов |
| src/core/math (только математика) | Ядро шире: 5 операций, включая схему и кодек | ARCHITECTURE.md |
| Bottom-sheet keypad-калькулятор | Обычный инпут + парсер выражений с предпросмотром | Интервью, раунд 2 |
| PNG-чек, рендер DOM в картинку | Только текстовая квитанция в буфер | Интервью, раунд 2 |
| SVG/Canvas-граф | Только чистый SVG + Vue-переходы | Интервью, раунд 2 |
| Playwright E2E (Page Object Model) | Не входит в v1: дымовые Vitest + приёмочные прогоны; Playwright — v2 | SPEC: Out of Scope |

Если Playwright-E2E захочется вернуть в v1 — это пересмотр спеки, а не решение агента.

## Процесс

1. Оркестратор берёт из [tickets/](../tickets/README.md) фронт (блокаторы закрыты) и
   назначает первичного агента.
2. Агент работает в своём scope, гоняет vitest до зелёного, отмечает чекбоксы,
   переводит Status = done.
3. Выход за scope или желание менять контракт — стоп и доклад оркестратору.
4. qa-acceptance подключается к закрытым экранам; его баги маршрутизирует оркестратор.
5. Оркестратор ревьюит на соответствие ADR/GLOSSARY и сшивает результат.
