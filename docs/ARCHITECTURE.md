# Архитектура «Делим»

Терминология — по дисциплине проектирования модулей: **модуль** (интерфейс + реализация),
**шов** (место, где живёт интерфейс), **адаптер** (конкретика, заполняющая шов),
**глубина** (поведение на единицу интерфейса, которому должен научиться вызывающий).

## Обзор: два модуля, один шов

Система состоит из двух модулей верхнего уровня. Весь домен спрятан за **одним внешним
швом — интерфейсом ядра**; Vue-оболочка тонкая. Это осознанный максимум глубины:
вызывающий (компонент, тест, зрительский экран) учит пять операций и получает всё
поведение приложения.

```
┌───────────────────────────── Оболочка (app, Vue 3) ─────────────────────────────┐
│  Экраны и компоненты (создание, расход, сведение, граф, зритель)                 │
│  Композаблы: useTrip (стейт+мутации+автосейв) · useHashRoute · useTheme          │
│  Адаптеры: localStorage · hash-URL                                               │
├────────────────────────── внешний шов: интерфейс ядра ───────────────────────────┤
│  ЯДРО (core, чистый TypeScript, ноль зависимостей от Vue/DOM)                    │
│  Интерфейс: 5 операций (ниже)                                                    │
│  Реализация: zod-схема · гроссбух · жадный + bitset сведение · кодек · парсер    │
│  Внутренние швы (приватные): solver-жадный ↔ solver-точный                       │
└───────────────────────────────────────────────────────────────────────────────────┘
```

Обоснование решений — в [adr/](adr/) (0003 чистое ядро, 0009 композаблы без Pinia).
Здесь — как это устроено.

## Ядро: интерфейс из пяти операций

Интерфейс ядра — единственное, что обязана знать оболочка. Всё денежное поведение
приложения выводится из этих операций; оболочка никогда не считает деньги сама.

1. **Схема (schema)**: собрать валидный стейт новой поездки; разобрать и провалидировать
   чужой стейт (версия схемы, лимиты, референциальная целостность) — либо успешный стейт,
   либо типизированная ошибка импорта с причиной (повреждена / другая версия / превышен лимит).
2. **Балансы (balances)**: стейт → баланс каждого участника в минорных единицах базовой
   валюты (гроссбух: расходы + сплиты + курсы + выплаты).
3. **Сведение (settle)**: балансы → минимальный список переводов. Гибридный контракт:
   жадный всегда, точный bitset-поиск при ≤ 12 участниках, детерминированный результат.
4. **Кодек (codec)**: стейт ↔ сжатая полезная нагрузка ссылки (lz-string), roundtrip без
   потерь; лимит длины полезной нагрузки на входе.
5. **Калькулятор (evalExpr)**: строка выражения (`+ - * / ( )`, запятая = точка) →
   значение в минорных единицах либо «некорректно».

Глубина ядра держится малым интерфейсом: сведение — один вызов, внутри которого скрыты
жадный и точный алгоритмы, сортировки и выбор лучшего результата. Внутренний шов между
двумя solver-ами приватный: тесты обращаются только к операции седения, а не к solver-ам
по отдельности (интерфейс — поверхность тестирования).

Условия интерфейса, о которых должен знать вызывающий (это часть интерфейса, не деталей):
балансы — целые минорные единицы; операция чистая (без побочных эффектов); результат
седения для одинаковых входных данных одинаков.

## Оболочка: композаблы и адаптеры

**useTrip** — единственный владелец мутируемого стейта: загрузка при старте, мутации
(участники, расходы, выплаты, курсы, завершение), автосохранение с дебаунсом ~500 мс.
Все производные величины (балансы, переводы, квитанция) — вычисляемые значения поверх
операций ядра, никакого дублирования логики в компонентах. Режим зрителя — тот же стейт
с заблокированными мутациями: один способ отображения поездки, а не два.

**useHashRoute** — роутинг без vue-router: `#/` активная поездка/создание, `#/archive`
архив, `#/t=…` зритель по ссылке. Хэш-навигация выбрана под GitHub Pages (без
SPA-редиректов) и под шеринг: ссылка поездки — обычный URL приложения.

Адаптеры оболочки тривиальны и заменяемы: `localStorage` (два ключа: активная поездка,
архив) и `location.hash`. Именно потому, что адаптеры тонкие, отказ от IndexedDB и Pinia
не создаёт технического долга — смена адаптера не трогает ни ядро, ни компоненты.

## Денежная модель

- Все суммы — целые минорные единицы; ввод «1500,50 ₽» сразу превращается в 150050.
- Курс — рациональное число (целая пара), вводится десятичной дробью и хранится точно.
- Конвертация долей — методом наибольших остатков: конвертированные доли в сумме точно
  равны конвертированному расходу. Инвариант «деньги не возникают и не исчезают»
  закреплён property-тестами.
- Расход и выплата хранят сумму+валюту; пересчёт в базовую валюту происходит при каждом
  вычислении балансов — правка курса меняет итоги задним числом бесплатно.

## Поток данных (однонаправленный)

```
UI-событие → useTrip.мутация → сериализуемый стейт поездки
                                    │ (автосейв, дебаунс)
                                    ▼
                              localStorage
                                    │ (вычисляемые)
                                    ▼
       balances(стейт) → settle(балансы) → экран седения · граф долгов · квитанция
```

Шеринг читает тот же стейт: codec.encode(стейт) → `#/t=…`; у получателя
codec.decode → schema.разобрать → useTrip в режиме зрителя. Зрительский путь проходит
через те же операции, что и тесты кодека и схемы, — шов один.

## PWA и деплой

vite-plugin-pwa с precache оболочки приложения; runtime-кэширования нет, потому что
сетевых запросов нет вовсе. Деплой — GitHub Pages по пушу в main; хэш-роутинг избавляет
от настройки редиректов.

## Тестовые швы

Единственный внешний шов — интерфейс ядра, через него проходят все три слоя тестов
(краевые случаи, property-based, exhaustive-сверка — см. [SPEC.md](SPEC.md)). Оболочка
покрывается дымовыми тестами экранов; отдельного шва для неё не заводим: она тонкая, и
тестировать её «в обход» ядра значило бы дублировать доменную логику.

## Чего в архитектуре сознательно нет

Второго шва между схемой и алгоритмами (это сделало бы модули мелкими), слоя «сервисов»
между композаблами и ядром (передачи без поведения), и абстракции хранилища ради
будущего IndexedDB — когда появится реальная вторая реализация, тогда и появится шов
(«один адаптер — гипотетический шов, два — настоящий»).
