# 05: Гроссбух — балансы из расходов и выплат

**What to build:** Операция ядра «балансы»: стейт поездки → баланс каждого участника
в целых минорных единицах базовой валюты. Внутри: сплиты (поровну/точно/долями) в валюте
расхода, конвертация по живым ручным курсам из настроек задним числом (ADR 0005),
распределение остатков конвертации методом наибольших остатков (ADR 0004), вычитание
выплат. Деньги не возникают и не исчезают: сумма балансов ровно ноль.

**Blocked by:** 02 (схема стейта)

**Status:** done

- [x] Расход в базовой валюте, поровну на 4: у каждого ровно четверть, сумма балансов ноль
- [x] Расход в чужой валюте с курсом-дробью конвертируется точно; при нецелености деления остатки распределены наибольшими остатками и сумма долей равна конвертированному расходу
- [x] Точные суммы и доли дают корректные дебеты; выплата уменьшает баланс плательщика и увеличивает получателя
- [x] Правка курса меняет балансы уже введённых расходов (живой курс)
- [x] Края: пустая поездка, один участник, расход без участников не проходит схему, нулевые суммы
- [x] Все проверки — через публичную операцию ядра, без заглядывания в промежуточные структуры

## Уточнение из тикета 12

Формулировка критерия «выплата уменьшает баланс плательщика и увеличивает
получателя» была реализована буквально и инвертировала смысл возврата денег:
выплата должника кредитором *наращивала* долг вместо погашения — противоречие
с ADR 0010 и user story 22. Исправлено в ветке t/12-payments (знак проводки
выплаты в computeBalances): деньги ушли от отправителя — его баланс растёт
на сумму, у получателя — падает; та же конвенция знака, что у плательщика
расхода. Тесты гроссбуха переписаны под погашение долга.
