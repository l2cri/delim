# 16: Завершение поездки, удаление и архив

**What to build:** Организатор завершает поездку (с подтверждением и финальной
квитанцией/ссылкой под рукой) — она уходит в архив глубиной 1, доступный только для
чтения по `#/archive`; старт новой поездки заменяет архив (с явным предупреждением)
(ADR 0002). Это замыкает жизненный цикл единственной активной поездки.

Плюс «аварийный выход»: удаление активной поездки целиком, минуя архив. Закрывает капкан
ошибочно созданной поездки (пока тикеты 10/16 не построены, после создания вернуться к
экрану создания невозможно): если ошиблись в названии или базовой валюте — поездку можно
снести и создать заново. Пустая поездка при «Завершить» предлагает удаление вместо
архивации — мусорный архив глубиной 1 не создаём.

**Blocked by:** 12 (выплаты — цикл расчётов завершён, есть что архивировать)

**Status:** done

- [x] «Завершить» у поездки без расходов и выплат предлагает удаление вместо архивации
- [x] Архивная поездка открывается только для чтения с видимой пометкой

## Заметки тикет-сессии

- **Зоны по AGENTS.md:** стейт вёл агент под чартером app-state, UI — под чартером
  ui-craft (спавн типизированных субагентов снова блокировался платформой, прецедент
  #07/#12); контракт useTrip (архивные refs + finishTrip/deleteTrip/замена при старте)
  зафиксирован оркестратором до начала работ и не менялся. Оркестратор сделал
  GUI-прогон браузером (создание → завершение → архив → замена → удаление) и два
  мелких фикса (опечатка, aria-label кнопки «Назад»).
- **Инвариант хранилища:** архив занят ⟺ активной поездки нет. `finishTrip` пишет
  архивный ключ СНАЧАЛА и только потом чистит активный (отказ хранилища не оставляет
  «ни активной, ни архивной»); `createTrip` затирает архив только при успехе — при
  отказе валидации прежний архив жив. Отложенный дебаунсом автосейв не воскрешает
  активный ключ после завершения/удаления (колбэк пишет только при живой поездке) —
  закрыто тестами обеих гонок.
- **«Квитанция под рукой»:** ReceiptCard остаётся на экране архива — финальную
  квитанцию можно скопировать и после завершения; на экране создания при занятом
  архиве баннер ведёт в архив до старта новой. «Ссылка под рукой» — ссылка поездки
  приходит с тикетом 15, экран архива её получит без переделок.
- **Черновики переживают архив:** экран поездки/создания смонтирован всегда и лишь
  скрывается (`v-show`) на `#/archive` — задокументированное свойство «черновики
  переживают смену хэша» сохранено, дым это проверяет. Следствие: общие карточки
  получили `useId()` для заголовков (иначе дубли id в DOM при двух смонтированных
  экранах).
- **Критерий «ссылка на архивную»:** зрительского экрана ещё нет — тикет 15 идёт
  параллельно (`t/15-sharing`). Часть тикета 16 — архивный ключ как полный валидный
  TripState — готова и закрыта тестом (parseTripState roundtrip, статус completed);
  сквозная проверка «открыл ссылку — видишь архивную поездку только чтением» ложится
  на приёмку тикета 15 (там рендер зрителя), пометка «только чтение» у зрителя
  завершённой поездки — одна строка на их экране.
- **Повреждённый архив** не мешает активной поездке (независимые ключи): экран архива
  показывает причину и предлагает удалить только архивный ключ (образец — LoadErrorScreen).
