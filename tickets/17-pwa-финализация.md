# 17: PWA-финализация, тосты и приёмочный проход

**What to build:** Финальный проход перед релизом v1: полный сценарий офлайн (создание
поездки, расходы, курсы, выплаты, сведение, квитанция — всё без сети после первого
открытия), авто-тема тёмная/светлая по системе на всех экранах, лимиты мягко подсвечены
в UI до попытки превышения, иконки/манифест/мета на месте, деплой на GitHub Pages зелёный.
Чек-лист приёмки прогоняется по [SPEC.md](../docs/SPEC.md) целиком.

**Тосты вместо нижней строки.** Сейчас все сообщения-отказы и подтверждения на экране
поездки (участник занят, лимиты, валюта в использовании, результат копирования ссылки)
рендерятся абзацем в самом низу разметки — на телефоне это за пределами видимости,
далеко от места действия. Заменить на тосты: фиксированная позиция в зоне видимости,
появление/исчезновение с анимацией, автоскрытие (~3–4 с), закрытие тапом, `aria-live`
для доступности; тон error/warn/info сохраняется. Нижний абзац-notice убрать; successes
кнопок, у которых уже есть локальная обратная связь (квитанция), не дублировать тостом.

## Заметки тикет-сессии

**Что сделано.**

- `Toast.vue` — тост вместо нижнего абзаца-notice: карточка-див внизу вьюпорта
  (`fixed`, `pointer-events-none` на обёртке — не блокирует страницу), safe-area через
  `env(safe-area-inset-bottom)` (viewport-fit=cover уже был), появление/уход — Vue
  `<Transition>`, автоскрытие 4 с с гашением таймера при смене notice и unmount
  (урок дебаунса из trip-screens.test.ts), закрытие тапом по растянутой на карточку
  кнопке. Роль и `aria-live` — на карточке: error/warn — `alert`/`assertive`,
  info — `status`/`polite`; роль на самой кнопке перекрыла бы её семантику для
  скринридера (P4 приёмки, исправлен в `ee0eb6c`). Тон-палитры сохранены и парны в
  тёмной теме. Квитанция тостом не дублируется — у неё локальное «Скопировано ✓»
  (смок в toasts.test.ts).
- Лимиты видны заранее: счётчики «X из N» уже стояли у участников/расходов/выплат/валют;
  добавлена длина ссылки — `encodedLink` computed (единое место сборки ссылки для
  копирования и подсказки) и янтарная полоса под шапкой при превышении
  `SHARE_PAYLOAD_WARN`, называет число символов, ничего не блокирует (ADR 0007).
- Тема: два `meta theme-color` по `prefers-color-scheme` (светлая — акцент, тёмная —
  zinc-950); аудит тёмных классов по всем 16 UI-файлам скриптом-проверкой пар —
  найдено и починено 2 непарных `placeholder:text-zinc-400` (CreateTripScreen,
  CurrenciesCard).
- CI: ci.yml теперь гоняет тесты на пуш в любые ветки (WORKFLOW.md это заявлял,
  конфиг — нет).
- Смоук-тесты тостов и полосы длины (qa-acceptance): `tests/smoke/toasts.test.ts`,
  7 тестов; полный прогон 29 файлов / 403 теста зелёный, `npm run build` зелёный.

**Приёмочный прогон (qa-acceptance).** По всем 42 user stories спеки — вердикт
«работает»; подтверждение — существующие смоуки (28 файлов), новый toasts.test.ts,

(dark-on-dark, косметика). Оба — кандидатам в «Замечания ревью».

**GUI-прогон оркестратора** (IAB Chromium, вьюпорт 390×844, системная тёмная тема,
сборка `vite build` + preview): первое открытие — SW activated и контролирует страницу,

удаления занятой Ани — мгновенно и с автоскрытием (реальное ожидание >4 с), шеринг —
info-тост «Ссылка скопирована», закрытие тапом. **Офлайн:** сервер заглушён →

вернул данные из localStorage после перезагрузки при мёртвом сервере. Скриншот 390px:
тёмная тема без «белых пятен», тост внизу заметен без скролла и не перекрывает контролы.
