# 07: Точное сведение (до 12 участников)

**What to build:** Второй solver ядра — точный bitset-поиск минимального числа переводов,
включается при ≤ 12 участниках и используется, когда он лучше жадного; выбор скрыт внутри
операции седения (внутренний шов, наружу не течёт — ADR 0006). Плюс exhaustive-сверка:
для n ≤ 6 эталонный полный перебор сравнивается с результатом седения на всех профилях
балансов из небольшого пространства сумм.

**Blocked by:** 06 (операция седения с жадным базовым алгоритмом)

**Status:** done

- [x] Случай, где жадный даёт лишний перевод (например, два нулевых подмножества), сводится точным короче
- [x] При n = 12 точный поиск укладывается в разумное время; при n = 13 не запускается
- [x] Exhaustive-сверка n ≤ 6: сведение никогда не хуже эталона, на провалах — понятный диф
- [x] Наружу поведение одно: вызывающий не выбирает solver и не знает, какой сработал

## Заметки тикет-сессии

Спавн субагента algo-core блокировался платформой — реализацию вёл general-purpose
субагент под явным чартером algo-core (зона src/core/ и его тесты); ADR-комплаенс и
стабильность интерфейса ядра оркестратор проверил независимо.

## Замечания ревью

Ревью-сессия code-review (Standards + Spec) по ветке против merge-base с master:
жёстких нарушений и P1/P2 нет, к мержу препятствий нет. P3/P4 ниже — не блокируют:

- SPEC Testing Decisions п.3 требует exhaustive-сверку «против обоих алгоритмов»;
  текущий exhaustive-тест (n ≤ 6, 11 057 профилей ±3) сверяет эталон только с
  операцией settle — жадный сверен точечно через независимый оракул в двух тестах.
  Расширение exhaustive-прогона на жадный-оракул — тикету 08 (владеет property/
  exhaustive-слоем седения).
- Пиннинговые тесты фиксируют точный порядок переводов точного слоя (тай-брейки
  групп из шапки settle.ts) — прецедент питч-теста 06, порядок документирован как
  контракт. Рефакторинг, меняющий детерминированный вывод при сохранении контракта,
  сломает пиннинг — осознанно принятое обязательство.
- ADR 0006 говорил «участников ≤ 12», код считает ненулевых, — расхождение снято
  уточнением ADR в этой же ветке (стоимость поиска 2^n растёт с числом ненулевых).
- Тайминговый ассерт «тяжёлый профиль 12 ненулевых < 1000 мс» (performance.now(),
  запас ×100 к факту) — классический кандидат на флак в CI; при вспышке заменить
  на сверку результата с известным оптимумом без часов.
- Случай «13+ участников, из которых ≤ 12 ненулевых» (точный слой запускается —
  порог по ненулевым) не покрыт прямым тестом — кандидат в тесты тикета 08.
