# 09: Расходы — три режима сплита

**What to build:** Организатор добавляет и редактирует расходы: название, плательщик,
сумма с валютой (с калькулятором-выражением из 04) и сплит — поровну между выбранными,
точными суммами или долями. Сохранение блокируется, пока сплиты не покрывают сумму
(с понятной подсветкой недостающего/лишнего). Список расходов показывает название,
плательщика, сумму и эквивалент в базовой валюте. Расходы удаляются свободно.

**Blocked by:** 03 (поездка и участники), 04 (инпут-калькулятор), 05 (балансы для конверсии в базовую валюту)

**Status:** done

- [x] Расход сохраняется в каждом из трёх режимов; переключение режимов не теряет осмысленных данных
- [x] Несходящийся сплит нельзя сохранить; расхождение показано суммой
- [x] Поровну с нецелой суммой распределяется корректно копейками (остатки — наибольшими)
- [x] В списке — эквивалент в базовой валюте по текущему курсу
- [x] Редактирование и удаление расхода работают; автосохранение подхватывает

## Заметки тикет-сессии

- Интерфейс ядра расширен решением оркестратора: `splitAmounts` и `convertToBase`
  (src/core/splits.ts) — производные денежные отображения тех же правил гроссбуха;
  общие помощники вынесены в приватный src/core/internal/. Оболочка денег по-прежнему
  не считает (ARCHITECTURE: «оболочка никогда не считает деньги сама»).
- Правило сходимости сплита живёт один раз в стейте: `splitDelta` (validation.ts);
  мутации addExpense/updateExpense/removeExpense в useTrip отказывают типизированно.
- Субагенты проекта блокировались средой исполнения; зоны core/state/ui/test
  выполняли general-purpose-агенты с чартерами ролей, вложенными в задание
  (зоны файлов соблюдены, ревью оркестратора после каждого этапа).
- Флакер автосейва из тикета 03 воспроизведён в этой ветке (6/10 полных
  прогонов) и понят: реальный таймер отложенного дебаунса переживала resetModules
  и дописывала поездку прошлого теста в общее хранилище. Независимо закрыт на
